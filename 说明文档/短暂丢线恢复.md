# 短暂丢线恢复

原逻辑在首次遇到不可用线路时立即执行 `Motor_Stop()`，400 ms 只延迟故障锁存，不能消除短暂全白造成的顿停。

## 当前行为

- 正常循迹时保存最近一次可用线路偏差。首次全白（`TRACK_LOST`）进入低速找线，默认最长 400 ms。
- 找线期间基础 PWM 为 200/1000，按上次偏差加入最多 ±100 的转向差值；居中丢线时直行，偏左或偏右时沿原方向缓转。左右电机保持正向，最大指令 300/1000。这是开环 PWM，不代表实际车速。
- 回线仍需循迹模块连续 3 个新帧确认。确认前的 `TRACK_AMBIGUOUS` 可延续本次找线，但不会重置计时；该状态也包含分离黑簇，因此找线窗口内并不保证已经正确找到单条线路。
- 一开始就是模糊线路时立即停电机，不主动找线。数据无效或过期立即停止本次找线，只有恢复可用线路才重新循迹。
- 不可用线路持续达到窗口上限，停车并锁存 `CAR_ERROR_TRACK`。障碍物检测优先切入避障；测距无效、手动停止和确认终点仍可停止运动。
- 稳定回线后重新从循迹模块的低速起步值输出，按原有加速规则恢复速度。

## 参数

均在 `App/CarConfig.h`：

| 参数 | 默认值 | 用途 |
|---|---:|---|
| `CAR_TRACK_LOSS_TOLERANCE_MS` | 400 ms | 不可用线路窗口；设为 0 时首次异常即故障停车 |
| `CAR_TRACK_RECOVERY_DEMAND` | 200 | 找线基础 PWM |
| `CAR_TRACK_RECOVERY_CORRECTION` | 100 | 最大转向差值 |

实际能否跨过断线、是否足以在弯道回线，取决于车速、电机起转占空比和探头位置，需实车标定。
