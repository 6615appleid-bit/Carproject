# 八路循迹串口接入与联调

## 为什么选择串口

模块支持八根 IO、USART 和 I2C 三种读取方式。现有小车电路图的红外接口只有 PA2、PA3、5V、GND，
而新增资料里的 STM32 串口接线表正好使用这四根线。因此当前实现采用 USART2，
通过两根信号线接收八个探头，不把 PA2/PA3 当成两个独立探头。
这是依据现有接线图作出的软件配置；上车时仍要核对实物插头方向。

## 接线

| STM32F103C8 | 八路模块 | 作用 |
|---|---|---|
| PA2 / USART2_TX | RX | 主控发送模式命令 |
| PA3 / USART2_RX | TX | 模块发送八路数据 |
| 5V | 5V | 模块供电 |
| GND | GND | 共地 |

串口参数为 115200、8 数据位、1 停止位、无校验、无流控。
模块上的 X1～X8 独立 IO 引脚在此方案下不接到主控。
原电机 TIM1、超声波 TIM3/EXTI0/1 和平台 SysTick 保持分工，USART2 不占用这些资源。
（超声波原来用 TIM4，现已改为 TIM3 以腾出 TIM4 给右轮编码器；触发/回波引脚不变。）

## 模块校准

依据模块使用说明，每次模块上电至少等待 20 秒。第一次使用、改变高度或环境时需重新校准；
校准值保存在模块中，普通断电后不用每次重做。
（这 20 秒是模块自身的上电稳定要求，针对下面这套 KEY 校准操作；车上的固件只等 5 秒就开始请求数据，
  两件事不要混为一谈，固件等待值见「软件数据流程」和文末说明。）

1. 先只给模块供电，主控保持复位，或临时断开主控 PA2 到模块 RX 的命令线。
2. 等待至少 20 秒，长按模块 KEY，红灯常亮后进入校准。
3. 按实际运行高度，让全部探头处于黑色区域，静置 3 秒，再短按 KEY 记录黑色。
4. 保持同样高度，让全部探头处于白色区域，静置 3 秒，再短按 KEY 记录白色。
5. 红灯熄灭表示成功；持续慢闪表示失败，需要重新校准。
6. 恢复串口接线，释放/复位主控，等待固件的预热（5 秒）后进行调试。

主控会发送 `$0,0,1#`，其中第一个 0 表示退出校准，所以校准过程中应避免主控的模式请求打断操作。
固件不会自动替你采集黑白标定值，预热和校准是两件事。

## 软件数据流程

```text
Track_Init → 配置 USART2，保持 INVALID
等待 5 秒（TRACK_WARMUP_MS = 5000U，不阻塞主循环）
发送 $0,0,1# → 模块开始发送数字流
USART2_IRQHandler → 验证并保存最新完整帧
Track_SenseUpdate → 消费新帧、分类、确认稳定
Track_Update → 线偏差 → 目标航向角 + 目标速度（Track_GetDrive）
CarControl → Heading_Drive → 转向环产生左右轮差速 → Motor_SetDemand
```

2026-09-23 起，循迹不再直接算 PWM 差速：`Track_Update` 只产出「目标航向角 + 目标速度」，
差速由 `Hardware/Heading.c` 的航向环（陀螺闭环）产生。详见 [Hardware 接入记录](README.md)。

无新鲜数据时每 1 秒重试模式请求；串口发送和接收都通过中断处理。
数字帧格式固定为：

```text
$D,x1:1,x2:1,x3:1,x4:0,x5:0,x6:1,x7:1,x8:1#
```

上例中央两个探头检测到黑线；黑线 0、白色背景 1。
默认 X1 在车体左、X8 在右；这里的“左/右”以车的前进方向为准，不能仅凭从板子背面看的左右判断。
本车实测转向相反，`track.c` 顶部 `TRACK_REVERSE_ORDER` 已默认设为 1；若以后更换探头安装方向，再把它改回 0。

全部白色为 LOST，六路及以上黑色为 WIDE，分离黑点簇为 AMBIGUOUS。
单个连续黑点簇需三个新有效帧确认，每次计数至少间隔 10 ms；超过 150 ms 没有新有效帧为 INVALID。
断线不会把最后一次正常线路结果永久保留。UART 协议没有校验和，不能识别所有传输位错误。

## 与 Avoid 的衔接

TrackStatus 仍只有 state/error；新增只读 Track_GetSampleId 供 Avoid 区分新帧。
CarControl 的原调度顺序不变：先更新感知，再选择 Track_Update 或 Avoid_Update。
避障寻线必须收到五个不同的新帧，线路 NORMAL、偏差绝对值不超过 300 且无障碍，
才停车并锁存 DONE。重复使用一帧跨五个控制周期，不算五次稳定回线。

## 首次软件调试

打开 Keil 的 `CarControl_Hardware_STM32F103C8` 目标并编译。
等待 5 秒预热、完成串口采集后，通过原 debug_command=1 请求启动。
debug_result=0 表示启动条件未满足，可检查线路状态、测距有效性及模块是否校准。
默认基准电机需求 300 是开环占空比需求，PD、速度、绕障时间都需要实车标定。
目前仍未实现正式启动按钮、起始横线驶离和终点识别，不能直接把 WIDE 当成终点。

- `八路巡线红外传感器/1.单板主控/2.STM32/串口/STM32-串口方式.pdf`：PA2/PA3 交叉接线、115200 串口示例。
- `程序源码/1.单板主控/2.STM32上位机源码.zip` 中的串口 `BSP/app_usart2.c`、`BSP/bsp_usart.c`：协议与串口配置参考。

模块说明建议上电后等待更久（其示例代码只有 1 秒）；本固件采用 5 秒（`TRACK_WARMUP_MS = 5000U`），
需要更长预热时直接改大这个宏即可。
主说明 I2C 的 X1 示例里，二进制 01111111 / 十进制 127 对应十六进制 0x7F，文中的 0x8F 不一致；
当前使用串口逐字段解析，不依赖该 I2C 示例。

完整 ARM 编译链接、UART/真实模块联合测试、电机测试、超声波测试及调度回归全部通过。
这些是软件验证，尚未连接实车或烧录验证。
